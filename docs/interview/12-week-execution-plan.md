# 12-Week Interview Execution Plan

This plan assumes roughly three hours per day and targets Senior Java/Backend Engineer interviews. Adjust problem counts downward when work is busy, but keep the timed sessions, mocks, and application work.

## Standard week

- Coding: 10–12 carefully reviewed problems, including 2–3 unseen timed problems.
- System design: one concept block plus one complete design.
- Behavioral/project: draft or rehearse two stories or project sections.
- Java or Spring/Hibernate: one focused topic answered aloud.
- Execution: one recorded session or mock, followed by a written correction plan.

## Month 1 — Foundation and baseline

### Week 1: Establish the baseline

- Complete one timed medium coding problem without preparation and record the gaps.
- Practice arrays, strings, hash maps, and sets.
- Learn the system-design interview structure and design a URL shortener.
- Select two anchor projects and draft the technical-challenge story.
- Audit the resume: every claim must be defensible.
- Build the first target-company list and choose a first-application date.

### Week 2: Common coding patterns and requirements

- Practice two pointers, sliding window, and prefix sums.
- Design a rate limiter and explain alternative algorithms.
- Draft the architecture-decision and production-incident stories.
- Review Java object contracts, collections, generics, and exceptions.
- Record a 45-minute coding simulation.

### Week 3: Trees and request/data flow

- Practice tree DFS, BFS, BST, recursion, and lowest common ancestor.
- Design a notification service or news feed.
- Complete the architecture diagram and scale facts for anchor project one.
- Review Spring request flow, dependency injection, validation, and error handling.
- Submit the first applications; do not wait for full readiness.

### Week 4: Graphs and first full mocks

- Practice graph traversal and topological sorting.
- Run the first complete system-design mock.
- Draft the performance, conflict, and ambiguity stories.
- Review SQL indexes, query plans, transactions, and isolation.
- Review Month 1 misses and schedule spaced repetitions.

## Month 2 — Interview-level execution

### Week 5: Heaps, queues, and messaging

- Practice heaps, priority queues, and interval problems.
- Design a chat system or event-processing pipeline.
- Review Kafka partitions, consumer groups, ordering, offsets, retries, and duplicates.
- Finish anchor project two’s architecture and metrics.
- Complete one coding mock and one behavioral recording.

### Week 6: Linked structures and stateful workflows

- Practice stacks, queues, and linked lists under time pressure.
- Design ticket booking or e-commerce ordering.
- Review Java concurrency, executors, futures, locks, visibility, and atomicity.
- Draft the failure and mentoring/influence stories.
- Tailor preparation to the most promising active interview process.

### Week 7: Dynamic programming and correctness

- Practice one-dimensional dynamic programming and selected backtracking.
- Design payments with idempotency, retries, and reconciliation.
- Review Spring transactions and JPA fetching, N+1 queries, locking, and batching.
- Rehearse all eight behavioral stories in two-minute versions.
- Complete a system-design mock and analyze pacing.

### Week 8: Advanced data flow and low-level design

- Practice graph variations, union-find, and shortest path.
- Design file storage or video streaming.
- Complete one low-level design and one machine-coding exercise.
- Review JVM memory, garbage collection, and production diagnostics.
- Target two full mocks this week and keep applications active.

## Month 3 — Simulation and targeted repair

### Week 9: Mixed unseen practice

- Stop topic-by-topic coding for most sessions; use mixed unseen sets.
- Design a distributed job scheduler or metrics/logging system.
- Complete a second low-level design with an interviewer-requested extension.
- Run a complete coding + behavioral mini-loop.
- Repair only weaknesses supported by mock or interview evidence.

### Week 10: Company-specific preparation

- Use target-company formats to choose coding and design domains.
- Rehearse project deep-dives against skeptical follow-up questions.
- Review networking, HTTP/TLS, load balancing, timeouts, and reliability patterns.
- Run a complete system-design + behavioral mini-loop.
- Refine questions for recruiters, managers, and engineers.

### Week 11: Full-loop simulation

- Run at least one multi-round simulation across coding, design, and behavioral.
- Practice recovering aloud after a wrong assumption or coding bug.
- Review only the highest-frequency misses and spaced-review queue.
- Keep scheduling real interviews and protect recovery time between rounds.

### Week 12: Stabilize, do not cram

- Re-solve representative problems from every major pattern.
- Deliver one final system design and all eight behavioral stories without notes.
- Review project facts, resume claims, and company notes.
- Reduce volume before interview days; prioritize sleep, pacing, and clear thinking.
- Use real interview feedback to choose the next cycle rather than restarting the whole plan.

## Weekly exit criteria

Before moving to the next week, update the [progress tracker](./progress-tracker.md) with evidence, name the largest recurring weakness, and choose one corrective drill. Unfinished volume can roll forward, but unresolved feedback must not disappear.
